# 发布、成本与验收

## 交付前核对发布对象

先确认当前源码目录、AppID、环境、API传输方式、后端版本和涉及的云函数。参考文档/旧压缩包/桌面备份不能取代当前项目。

- 小程序：原生源码 → 开发者工具编译/上传 → 体验版本 → 真机 → 审核/发布。
- 后台与 API：运行代码和构建依赖 → 后端部署包或镜像 → 云服务部署/版本切换。
- 云函数：只有变动及依赖影响的函数分别部署，检查运行环境、依赖、变量和触发器。
- 数据库：结构迁移、兼容旧代码和回滚/前滚计划单列；重新上传前端不改变数据库。

一次跨端变更要明确部署顺序与旧客户端兼容性。记录版本、时间、SHA-256和包含功能；打包成功只证明创建了产物，不能写成已上线。

## 配置导致的真机故障

本地回环地址在手机上指手机自身，局域网地址要求同网且不是正式域名。体验/生产用已选方案的 HTTPS/云调用，校验官方要求的域名、证书、环境关联和应用权限。不能假定腾讯云默认域名一定可在任意微信场景直接使用。

运行时 console 注入的地址/授权不随上传保存。新安装/清缓存/旧版本缓存分别验收，不能只在已配置的模拟器上测试。正式发行不能依赖关闭合法域名校验、用户手动粘贴管理员密钥、通用测试密码或模拟手机号身份。

`miniapp_preflight.py` 是静态启发式检查：验证入口配置、文件引用存在性、公开 API 地址、源文件预算和若干常见秘密模式。对未知 ignore 类型报提示；不会准确模拟微信编译、DNS/证书、云权限或平台资格。若用 callContainer/云函数，按实际官方通道另行验证并记录，不为了通过脚本伪造 HTTP URL。

## 打包原则

白名单包含精确运行文件，禁止本地数据库、密钥、真实业务资料、虚拟环境、测试目录、历史包及 macOS 元数据。构建依赖由受锁定的包管理器/构建步骤获取，不把整个 node_modules 或 venv 混进去。

通用 `package_release.py` 只处理已经明确的精确文件清单，默认 dry-run，`--write` 才创建 ZIP及文件哈希清单；产物在源目录之外，拒绝覆盖和符号链接。backend 清单不应含小程序与云函数；cloud-function 清单只含目标函数及其实际依赖。工具不负责替你决定完整运行依赖，Docker构建或目标运行测试仍需执行。已有成熟打包脚本时先核对，再优先沿用，不为了套 Skill 重写它。

## 分层测试记录

| 层级 | 应验证 | 不能推导 |
|---|---|---|
| 单元/接口 | 校验、状态机、数据归属、金额/配额、幂等、拒绝越权 | 真机可用/部署正确 |
| 两端集成 | 一端修改另一端读取；独立角色交叉操作；状态恢复 | 平台审核通过 |
| 模拟器/浏览器 | 真实渲染、布局、点击、导航、后台表单与错误处理 | 手机硬件和系统能力 |
| 云端隔离数据 | 同版本接口、存储与附件、环境边界、权限 | 整体生产压力能力 |
| 真机 | 清缓存/更新、登录授权、图片音频、相机/手势/振动、切后台、弱网 | 审核和业务运营签字 |
| 运维 | 服务重建恢复、备份与异机还原、告警、定时任务、容量与目标负载 | 健康接口200已等价完成 |
| 平台/业务 | 实际审核发布状态、合规材料、经营规则与真实样本签收 | 最新本地修改已部署 |

对关键动作测试双击、并发、提交成功但响应丢失、401/403、409、附件临时URL失效、断网恢复、旧版本数据。不得自动重试非幂等写操作。测试账号/数据隔离和收尾按用户授权执行；真实账号密码无需为测试随意重置。

## 成本决策

用已确认负载做低/中/高情景：计算资源和最低常驻副本、数据库、对象存储容量与请求、流量/CDN、域名/证书、日志备份监控、短信/通知、AI输入输出/图片调用、平台认证/交易费用。一次性费用和年度费用分开，人工只有用户要求才计入。

标明地域、规格、活跃量、附件保留期、并发与调用量、优惠有效期及超额计费。免费额度、首购优惠、API Key 有效期、包年资源和平台备案资格不是同一件事。价格必须查当前官方规则，预算只是基于假设的估算，不能承诺固定总费用。

## 平台人工与外部步骤

按实际功能核对主体注册、开发成员授权、AppID、微信认证、服务类目、隐私声明与权限用途、备案和行业材料；线上支付还需对应商户与商品/服务资质。需求不涉及的审核不列为必需。法律/平台规则以当前官方材料为准，说明不能由代码替用户完成的提交/核验。

## 验收报告最小字段

范围、版本、环境、用例、预期/实测、证据位置、通过/失败/待验证/不适用及原因。最后列 P0阻断、P1改进、用户待办和下一步；不以通过多少测试掩盖未验收的身份/交易/恢复链路。
