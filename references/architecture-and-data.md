# 架构与数据决策

## 三端边界与功能契约

新工程可使用 `miniapp/`、`admin-console/`、`backend/`、按需 `cloudfunctions/`、`tests/`、`docs/`。已有项目沿用其实际结构；根目录和嵌套项目配置不一致时，以开发者工具实际导入的项目及其 miniprogramRoot 为准。

端到端变更顺序：定义服务端契约 → 业务验证/测试 → 小程序接入 → 中控接入 → 两端交叉验收。中控有入口不代表拥有权限，小程序隐藏入口也不构成权限控制。

功能契约至少含：发起者、资料所属主体、目标对象、前置状态、请求/响应字段、成功后的持久化事实、另一端可见结果、拒绝条件、取消/撤销、审计、重复请求和超时结果查询。

客户端不得自行决定会员生效、价格、余额、可用额度、复核通过或资料归属。服务端最小化响应字段，不向普通用户发送经营成本、管理员信息或他人资料。

## 身份、权益、对象与操作人分离

- 用户主体：稳定 ID；手机号是可变登录方式，不作为所有表的永久主键。
- 登录凭据：微信身份、手机号验证或员工认证；登录/绑定与权益授权是两条流程。不能信任客户端提供的 openid、ownerKey、员工 ID 或手机号作为独立证明。
- 使用对象：家庭成员、宠物、设备、客户等；付款人/聊天人不一定是服务对象。
- 权益：套餐、额度、有效期、门店和设备限制，由服务端校验。前端缓存仅用于展示。
- 操作记录：主体 ID、操作时的登录号码或凭据标识、对象 ID、动作、时间、版本/请求 ID。历史显示不能因换手机号被重写；不记录密码/token。
- 撤销：停用账号、号码或设备后，旧会话失效；重新启用不自动复活旧 token。

Cookie 控制台使用适当的 Secure/HttpOnly/SameSite，并按实际跨域结构防 CSRF；令牌式客户端采用受控有效期、撤销与日志脱敏。隐藏后台 URL 只减少误访问，不能替代认证。

## 先按负载和损失容忍度选数据库

| 方案 | 可考虑的前提 | 必须说明/验证的限制 |
|---|---|---|
| 本地 SQLite＋私有对象快照 | 单个写实例、规模适合、允许按最近成功快照恢复、预算敏感 | 容器磁盘可能丢失；使用一致性快照；多个库的快照一致点；加密/最小权限；备份失败告警；真实重启/重建恢复；不能直接开多副本 |
| 托管关系数据库 | 多实例、多岗位同时写、金额/配额/库存等强一致需求或更严格运维目标 | 事务边界、唯一约束、幂等、索引、容量、连接池、备份与恢复；高可用规格按实际目标决定，不一律购买最贵档 |
| 云开发文档数据库 | 与集合权限及云函数模型契合、查询/事务限制能满足业务 | 拒绝客户端越权；确认集合规则、查询限制和事务边界；不能默认它与 PostgreSQL API 兼容 |
| 对象存储 | 图片、语音、文档、导出、数据库快照 | 不提供一般关系事务，不当作 SQLite 随机读写磁盘；对象 URL 可过期、权限须随资料归属校验 |

不要把“用了 PostgreSQL”当成已经适合高并发。如果整个业务存成一份带 revision 的快照，仍可能在无关写入之间冲突；按目标负载评估，必要时拆成实体表。用 409 保护旧版本覆盖有价值，但必须给可恢复的 UI，不能自动重放收费动作。

## 一致性与故障恢复

- 一次业务变更的关键状态一起提交；成功响应应有明确的持久化语义。
- 关键写操作使用服务端可验证的幂等键，并记录结果；同键不同参数拒绝，超时查原操作。
- 金额使用最小货币单位整数或明确十进制定点，定义舍入、退款、可用额度和待审核预占。
- 资料更新用实体版本/条件更新；发生冲突提示刷新并核对，不静默覆盖。
- 附件先上传、业务后提交时考虑孤立对象；提交结果不明不能立刻删除可能已引用的文件。清理需延迟、核对引用并保留审计。
- 恢复测试验证内容、记录数量/关键汇总、附件哈希与可访问性；不能只验证备份文件存在。
- 快照恢复的 RPO（可接受丢失窗口）与 RTO（可接受恢复时间）用用户业务语言确认，不能承诺零丢失。

## 独立部署与 SaaS

批量为不同客户建立独立部署，可共用开发流程和模块模板，但各自配置与数据隔离。共享 SaaS 另需租户认证上下文、所有查询/附件/后台任务的租户约束、租户级测试与升级迁移。绝不靠前端传入 tenant_id 获得访问权限，也不以换名称/颜色冒充多租户完成。
