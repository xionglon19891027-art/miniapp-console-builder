# 两端体验与附件

## 品牌与密度

复用设计方法，不复制案例商标、IP或客户图片。统一字体层级、间距、按钮尺寸、图标线宽和语义色；危险/警告/成功颜色可不同，不为统一而消除语义。图标优先复用项目资源，增加前确认许可和包体成本。不为丰富而给每个图标垫色块。

小程序先考虑拇指操作、键盘遮挡、安全区和窄屏；中控考虑表格密度、长内容、批量动作与键盘操作。减少文字堆叠，通过标题、辅助说明、状态、动作分层表达。

## 弹层与微交互

业务弹窗可用统一组件；系统授权和平台原生控件按平台能力保留。统一遮罩层级、关闭规则、焦点和滚动锁，避免看得见但点击被透明遮罩吃掉。

按钮按下、禁用、忙碌、成功/失败有明确反馈；页间动画轻量且不阻塞操作。新请求覆盖旧请求、连续点击、离开页面时清理定时器/音频/监听。动效适配低性能设备和减少动画设置；振动/音效按系统支持与用户偏好降级。

吉祥物只是可选品牌功能。动画优先使用能稳定在目标设备运行的方式；避免高频 setData 驱动大范围更新；新动画需连续点按、滚动和输入共存测试。鼠标跟随不能直接搬到手机，触摸反馈和随机动作要按场景重新设计。

## 图片、语音与包体

- 真机采用平台实际兼容格式，检查文件内容和扩展名一致。高压缩比不证明视觉或解码兼容，须在对应设备验收。
- 复用背景图及既有素材；压缩保留尺寸、透明通道和关键细节，做前后视觉对照。许可明确才分发素材。
- 包体以实际 miniprogramRoot 和 packOptions 为依据，排除后台/数据库/私密文件与元数据。源码预算应低于平台上限并留编译余量；必须再由开发者工具验包。
- 分包是否采用由产品和用户约束决定，不把“单主包”写为所有项目的硬性规则，也不能未经批准将用户拒绝的分包加回来。
- 图片预览的手机双指缩放不等于桌面上的“＋/－”按钮。确认手势缩放、拖动、退出、长按与归档不冲突。
- 附件尽量使用私有存储、授权读取或短期 URL；持久化 file ID/对象键和归属，不把会过期的临时 URL 当唯一记录。
- 核对 request/uploadFile/downloadFile 等实际使用通道的域名、TLS和身份头；本机能访问不等于微信允许。

## 验收方式

先用明确截图/录屏描述缺陷，修复后在同入口、同尺寸复测。原生小程序必须看开发者工具实际渲染，浏览器模拟图不能替代。

若自动化点击无响应：看最新页面/遮罩/焦点，尝试受支持的真实点击方式，与其他页面对比。工具输入故障与产品触摸故障分别记录，不通过不断改 CSS 猜原因。一次验证后恢复临时调试代码；不能把 console 临时配置误当上传配置。

手机验收覆盖：双指缩放、录音权限与录放、静音/耳机、振动、真机键盘、相机相册、后台恢复、长按与点击、弱网。没有对应设备就标为待验证，不能用模拟 API 调用成功代替物理效果。
